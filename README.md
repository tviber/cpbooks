# 纸上算法

当前版本：**v0.0.1**。

一个可以动手操作的 Three.js 教学网站。首页直接打开第一章 Dijkstra 最短路，四张立体地图分别有 5、6、7、8 个站点。读者可以观看推演、改换起终点和比较走法。

页面采用浅色全屏实验台：立体书占据主视野，常驻界面只保留当前目标、实时结果与底部操作条。交互结构参考 [iamtechartist 的立体书演示](https://iamtechartist.com/demos/)，原理、代码和实验设置按需展开。

## 本地运行

需要 Node.js 22.12+。

```sh
npm ci
npm run dev
```

打开终端中的本地地址即可进入第一章。`/#dijkstra` 打开集市地图，原有的 `/#vector` 和 `/#binary` 书签也会转到这里。

```sh
npm test
npm run build
npm run preview
```

构建结果在 `dist/`。线上实验台位于 [books.cp4.fun](https://books.cp4.fun/)。

## CI 与自动部署

[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) 在推送 `main`、向 `main` 提交 PR，以及手动运行时执行验证：Node.js 22 → `npm ci` → `npm test` → `npm run build`。PR 仅运行验证，不读取部署密钥或发送部署通知。

`main` 验证成功后，Actions 尝试向 `https://txc.cp4.fun/hooks/deploy-main` 发送 HMAC-SHA256 签名的 JSON 通知，包含仓库名、`refs/heads/main` 和本次提交的完整 SHA。自动发布依赖服务器启用接收端和对应的部署脚本，按这个 SHA 从 codeload 下载源码并构建 `dist/`。手动运行工作流时也必须选择 `main` 才会通知服务器，其他分支仅验证。

首次启用需要在 GitHub 仓库的 **Settings → Secrets and variables → Actions** 中添加 `DEPLOY_WEBHOOK_SECRET`，值与部署服务器 `/etc/webhook-secret` 一致。不要将密钥写入源码或日志。未配置时验证任务仍可正常运行，部署任务会明确报错。接收端和密钥都配置好后可在 Actions 中手动重跑工作流。

部署通知按仓库串行发送，并设置连接与请求超时，不自动重试，避免重复触发异步部署。HTTP 2xx 和 Actions 的部署任务成功只表示通知被接收；服务器最终是否构建成功，需要查看 `/var/log/deploy-webhook.log`。当前接口未提供部署状态查询，CI 不会等待远端构建完成。服务器原有 `flock -n` 在忙碌时会跳过新请求，密集推送后应核对服务器日志中的提交编号，必要时等待上一轮完成后手动重跑最新提交。

接收端停用时，也可以在验证通过后通过 SSH 发布同一提交。先在独立目录完成构建，保存原入口，复制带内容哈希的资源，最后原子替换 `/srv/cpbooks/app/dist/index.html`。保留旧资源可让已打开的页面继续加载，也便于恢复原入口。

## 第一章 · Dijkstra 最短路

每一张图都有自己的站点、道路和用时。圆牌写的是路段耗时，方牌写的是从起点出发到该站的暂定总用时，✓ 表示已经确定。可以点「下一步」观察哪一块站牌被改写，再点「上一步」对照。进入「比较路线」后可直接查看到所选终点的完整走法。

| 场景 | 站点数 | 默认最短路线 | 用时 |
| --- | ---: | --- | --- |
| [集市](https://books.cp4.fun/#dijkstra/everyday/compare) | 5 | 邮局 → 花园 → 书店 → 码头 | 6 分钟 |
| [滨河栈道](https://books.cp4.fun/#dijkstra/riverside/compare) | 6 | 渡口 → 芦洲 → 船坞 → 灯塔 | 7 分钟 |
| [钟楼车站](https://books.cp4.fun/#dijkstra/clock/compare) | 7 | 站门 → 票厅 → 大厅 → 闸机 → 站台 | 7 分钟 |
| [双桥河谷](https://books.cp4.fun/#dijkstra/tie/compare) | 8 | 营地 → 石径 → 吊桥 → 清泉 → 山顶，或营地 → 松林 → 桁架桥 → 山脊 → 山顶 | 都是 8 分钟 |

有并列最短路时，点「换条走法」会同步切换道路高亮和算式。「返回推演」恢复本图的原步骤。切换地图会使用新图的默认起终点，实验设置可以更换出发站或跳步。讲解面板提供距离表、只记录一个前驱的 C++ 示例和非负权条件说明。无法启动 WebGL 时会显示可操作的平面路线图。

## 已下线章节（源码保留）

下面两章的教学规则、模型、操作和测试保留在仓库，网站已移除对应入口。

### C++ vector

- 初始状态为 `reserve(4)` 后添加 12、24、36，区分 `size` 和 `capacity`。
- 预测是否需要扩容；添加、移除末尾、预留容量、撤销和重置。
- 点击三维小屋或实验设置中的槽位，查看索引、值和示意字节地址。预留的空槽位不可访问。`reserve` 也在实验设置中，挑战时有直接入口。
- 容量不足时，新存储出现，已有元素迁移，旧存储折起；状态、操作代码和解释同步更新。
- 挑战：从空 vector 开始，装入 8 个元素，已有元素迁移次数为 0。
- 代价账本比较倍增和每次加 1 的策略，说明单次 O(n) 与尾部添加摊还 O(1)。

本实验最多 16 个槽位，使用倍增策略与逻辑存储区块；C++ 标准不规定固定增长倍率。`reserve(n)` 的演示分配恰好 n 个槽位，标准只保证 capacity 至少达到 n。假定 `sizeof(int) == 4`，真实值依平台而定；`data() + i` 自动按元素大小偏移。超过 8 个槽位在三维场景中折行显示，内存语义仍连续。

### 二分答案 · 砍树

- 以 [洛谷 P1873 EKO / 砍树](https://www.luogu.com.cn/problem/P1873) 为原型：锯片设置统一高度 H，得到每棵树高于 H 的部分，在木材至少 M 米时让 H 最大。
- 自由试砍：拖动滑块、书中的橙色手柄或点击高度刻度，实时查看橙色可收集部分与木材总量。点击“试砍”后才在书上展开每棵树的贡献与累计尺，并播放分离、累计动画；实验设置中可随时查看详细数值。
- 二分挑战：检验中点后自己决定保留哪段高度；错误选择给出原因，不破坏区间。被排除的尺段折起，支持撤销和重置。
- 完成时展示答案 H 的木材量与 H+1 的木材量，验证可行边界。最优木材总量可以超过需求，无需恰好等于需求。
- 五道预设题，覆盖同一森林的需求变化、第二个典型样例、合法答案 0 和木材总量不足。支持 2–6 棵树的自定义森林，也能直接修改木材需求。
- 默认树高 `[20, 15, 10, 17]`，需求 7 米，最高锯片为 15 米。区间 `[0, 20]`，中点向上取整，路径 `10 ✓ → 15 ✓ → 18 × → 16 ×`。

每次试砍恢复原始树高，输入树不排序。0 是合法高度，无解使用独立状态（代码示例返回 -1）；先检查总量足够，再进入二分。C++ 示例使用 `long long` 累计。树高限制 1–50 米，木材需求 1–500 米；树冠只表示外形，统计的是高度差的长度，不是体积。超过 25 米的三维高度尺简化文字，HTML 刻度保留每一个整数。

## 操作与设备

鼠标拖动旋转，滚轮或双指缩放；恢复视角、重置实验按钮位于场景右下方。手机使用独立的紧凑双行操作条。右上角面板分为讲解、C++ 代码、实验设置，方向键切换标签，Escape 关闭；所有三维点击都有 HTML 按钮等价操作，支持键盘与屏幕阅读器。系统“减少动态效果”设置会关闭开书和迁移动画。

### 界面约定

- 场景、出发站和终点复用原生 `select`。桌面菜单用浅绿底和勾号标出当前项，收起后以字段值表示选择。触屏用系统选择器。讲解面板复用原生 `dialog`、标签页和 `details`，折叠项与菜单共用细线箭头。控件圆角、字号、间距和品牌色来自 `src/style.css` 的主题变量。
- 首屏标题说明当前地图，场景选择与路线模式紧邻地图，推演结果紧邻底部操作条。逐步学习时“下一步”是主操作，自动演示作为次要选项；比较模式把路线和总用时放在终点选择旁。
- 手机按标题、场景、进度、地图、操作与反馈的顺序排布。管理和讲解入口保留在页眉，地图与操作区获得主要空间。
- 普通按钮点击只显示短暂按压和悬停反馈。模式开关、标签页和地图站点用 `aria-pressed` / `aria-selected` 传达需要持续可见的选择；键盘焦点通过 `:focus-visible` 保持清晰轮廓。

共享控件参考 computing-lab 的 `src/design/base.css`，以及 `origin/main` 上统一折叠箭头的 `68939bc` 和移除下拉框外框的 `fcbd110`。

首次打开首页从集市的邮局开始。点页眉品牌回首页时，会恢复当前标签页的地图、起终点、步骤和比较模式，浏览器前进与后退也会恢复对应状态；带场景片段的链接按链接内容打开。页面标题同步当前地图。学习进度也保存在当前浏览器，网页不执行任意 C++ 代码，没有账户或服务器存储。

## 结构

- `src/lessons/`：纯数据规则，与 Three.js 无关。
- `src/scene/`：纸艺模型、相机、拾取、资源释放和动画。
- `src/ui/`：浅色实验台、按步骤变化的操作条、地图站牌、各章的讲解与代码。
- `src/main.js`：用户操作、章节状态、撤销和完成标记。
- `tests/`：覆盖 vector 与砍树的边界条件，以及最短路演示中的选站、回退、路线改写和不可达站点。

与原仓库一样采用 Vite 和 Three.js。无需视频文件、外部 3D 模型或图片；中文标题优先使用 Noto Serif SC，网络字体不可用时回退到本机宋体。
